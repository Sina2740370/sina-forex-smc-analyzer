# سیستم چندایجنتی فارکس (MAS) — فاز ۱: هسته MVP

ایده‌ی مرکزی: به‌جای یک «امتیاز ترکیبی تک‌لایه» (نسخه قبلی — که روی ۴ سال داده E[r]=+0.015 و PF=1.02 داشت)،
**ایجنت‌های مستقل** تحلیل می‌کنند، با هم بحث می‌کنند، و سیگنال فقط بعد از عبور از **۷ گیت مستقل** و تأیید **ایجنت ریسک** صادر می‌شود.

ایجنت‌ها ماژول‌های **قطعی (deterministic) پایتون** هستند، نه LLM — تا سیستم قابل بک‌تست و تکرارپذیر بماند.

## معماری

```
A0 Coordinator (engine/mas/aggregator.py)
 ├─ A1 Data        (agents.py: run_data_agent)        پاک‌سازی + quality_score؛ <0.90 → توقف کل تحلیل
 ├─ A2 Regime      (agents.py: run_regime_agent)      ADX/ATR/EMA/BB/ساختار + سشن؛ در روند واضح رأی جهت‌دار
 ├─ A3 Technical   (agents.py: run_technical_agent)   چندتایم‌فریم + فیبو + مومنتوم + کاندید entry/SL/TP
 ├─ A4 Fundamental (fundamental.py)                فاز ۳: ییلد دیفرنشیال FRED (طلا: −ییلد واقعی)؛ بدون فید → stub
 ├─ A5 Sentiment   (sentiment.py)                  فاز ۳: صدک COT پول هوشمند ۳ ساله؛ بدون فید → stub
 ├─ A6 Liquidity   (agents.py: run_liquidity_agent)   سشن/سوئیپ/اسپرد
 ├─ A7 Debate      (debate.py)                        پرونده Bull/Bear، حاشیه اجماع ۸، تناقض‌ها
 ├─ ۷ گیت تصمیم (G1..G7) → A8 Risk Agent (risk_agent.py) با حق وتو
 └─ Signal (contracts.py) + اثر انگشت + گزارش JSON/Markdown (reports.py)
```

## قواعد کلیدی

- **قرارداد ایجنت:** هر دلیل باید `evidence` داشته باشد؛ گزارش بدون شواهد با `validate()` رد می‌شود.
- **داده غایب رأی نمی‌دهد:** ایجنت stub با `is_stub=True` از تجمیع حذف و وزنش بازتوزیع می‌شود؛
  اطمینان نهایی با «پوشش وزنی» (سهم وزن ایجنت‌های فعال) جریمه می‌شود. حدس ممنوع.
- **ماتریس وزن رژیم‌محور** (`weights.py`): وزن‌ها ثابت نیستند؛ در رونددار تکنیکال/رژیم، در رنج نقدینگی/سنتیمنت
  سنگین‌ترند. رژیم `high_vol` کل امتیاز را به مرکز ۵۰ جمع می‌کند (ضریب 0.85).
- **۷ گیت:** G1 امتیاز ≥ آستانه رژیم (رونددار 65 / رنج 70 / پرنوسان 75)، G2 حداقل ۳ ایجنت مستقل هم‌جهت،
  G3 هم‌خوانی رژیم/ساختار بلندمدت، G4 ریوارد/ریسک ≥ 1:2 با SL ساختاری، G5 تأیید ریسک، G6 پنجره خبری ±۱۵ دقیقه،
  G7 کیفیت داده ≥ 0.90 و تاریخچه کافی. هر WAIT با شناسه گیت و «شرط بازبینی مجدد» ذخیره می‌شود.
- **ریسک:** ۱٪ ریسک/معامله، ۳٪ همزمان، سقف ضرر روزانه ۳٪ و هفتگی ۶٪، حداکثر ۳ معامله باز و ۱ معامله/جفت،
  ۲ ضرر متوالی → نصف‌کردن حجم، ۳ ضرر → توقف، RR ≥ 2. حجم لات از pip value واقعی جفت‌ارز (بدون حدس).

## اجرا

```bash
# تحلیل نقطه‌ای روی داده واقعی (Dukascopy M15 در data_duka/)
python -m engine.cli mas-analyze --symbol EURUSD --csv-dir data_duka --now "2026-01-25 08:00" --out out_mas

# خروجی: out_mas/mas_EURUSD_BUY.json (JSON استاندارد سیگنال) + mas_EURUSD_BUY.md (گزارش فارسی)
```

اگر `--now` داده نشود، زمان فعلی UTC استفاده می‌شود. `--spread` اسپرد واقعی (بر حسب قیمت) می‌دهد؛
وگرنه اسپرد معمول نماد از `engine/mas/symbols.py` استفاده می‌شود.

## فاز ۲ — بک‌تست چندجفتی و فاز ۴ — پورتفوی چندجفتی

```bash
# فاز ۴: تحلیل همه نمادهای دارای داده در یک نقطه زمانی با AccountState مشترک
# (سقف ریسک همزمان ۳٪ در سطح سبد اعمال می‌شود)
python -m engine.cli mas-portfolio --csv-dir data_duka --out out_mas

# فاز ۲: بک‌تست walk-forward — هر سیگنال عبوری = یک معامله (SL/TP روی M15، اسپرد معمول نماد)
python -m engine.cli mas-backtest --csv-dir data_duka --step-hours 8 --out out_mas/backtest
```

- **چندارزی:** مشخصات همه نمادها (pip، ارزش پیپ، اسپرد معمول، فرمت رقم) فقط در
  `engine/mas/symbols.py` تعریف می‌شود؛ نماد جدید = یک ورودی، بقیه لایه‌ها خودکار.
  نمادهای بدون داده در گزارش سبد با خطای شفاف می‌آیند، نه حدس.
- **بک‌تست:** نقاط تصمیم هر `--step-hours` ساعت؛ ورود = کلوز + اسپرد جهت‌دار؛
  برخورد SL و TP2 در یک کندل = SL (بدبینانه)؛ ریسک ثابت ۱٪ با compounding؛
  در هر نماد حداکثر یک معامله باز (R-SYM). آمار تفکیکی رژیم/سشن در `bt_<symbol>.json`.

## فاز ۳ — داده بیرونی: A4 فاندامنتال و A5 سنتیمنت

- **A4 (fundamental.py):** تفاضل ییلد بلندمدت «بِیس − کوت» از FRED (بدون کلید، از fredgraph.csv):
  `DGS10` (آمریکا)، `IRLTLT01DEM156N` / `IRLTLT01GBM156N` / `IRLTLT01JPM156N` (ماهانه OECD).
  طلا: منفیِ ییلد واقعی آمریکا (`DGS10 − T10YIE`). امتیاز = 50 + 25·tanh(diff/1.5)؛
  اطمینان با تازگی داده (سری ماهانه تا ~۳ ماه قدیمی) کم می‌شود؛ قدیمی‌تر از ۴۵ روز → stub.
- **A5 (sentiment.py):** موقعیت خالص COT CFTC به‌صورت **صدک ۳ ساله هفتگی**:
  ارزها از گزارش مالی CME (Asset Mgr + Leveraged Money خالص؛ EUR 099741/GBP 096742/JPY 097741)،
  طلا از گزارش کالایی legacy (Noncommercial خالص، COMEX 088691).
  امتیاز = 50 + 20·(pctile−0.5)·2؛ صدک > ۹۰٪ یا < ۱۰٪ → پرچم متراکم‌شدگی و نصف اطمینان.
- **لایه داده (datafeeds.py):** کش دیسکی در `data_cot/` (گیت‌شده)؛ TTL فید روزانه ۲۴ ساعت؛
  `--offline` فقط از کش. شبکه/داده نبود → ایجنت stub صادقانه، رأی نمی‌دهد.
- **بدون lookahead:** هر دو ایجنت در نقطه زمانی `now` فقط ردیف‌های ≤ now می‌بینند (پیش‌نیاز بک‌تست)؛
  COT هفتگی است (تأخیر تا ۶ روز) و این محدودیت در `missing_data` ثبت می‌شود.

## محدودیت‌های جاری (صادقانه)

- تقویم اقتصادی بلادرنگ (G6) متصل نیست → G6 با هشدار پاس می‌شود؛ NFP/CPI لحظه‌ای پوشش داده نمی‌شود.
- ییلد OECD ماهانه است (تأخیر تا ۳ ماه) و COT هفتگی (تأخیر تا ۶ روز) — سهمشان در تجمیع با اطمینان پایین‌تر و ثبت در missing_data اعمال می‌شود.
- Execution واقعی وجود ندارد؛ خروجی «سیگنال اجرایی کاغذی» است.
- در بک‌تست، اسپرد لحظه‌ای/سلیپیج/سواپ شبیه‌سازی نشده‌اند؛ نتایج «توان تاریخی ستاپ‌ها» است، نه تضمین آینده.
- هیچ ادعای سودآوری وجود ندارد؛ قبل از هر استفاده واقعی، walk-forward و حساسیت پارامترها باید بازتولید شود.
